# learn — персональная среда обучения на Qwen Code

Аналог системы обучения из видео **«How I Use AI to Learn Things»** (Eero Alvar), перенесённый с конфигурации `pi` на **Qwen Code**. Философия обучения закодирована в skill, плюс субагенты для проверки фактов и рисования диаграмм, журнал занятий и слэш-команды.

- Видео: https://www.youtube.com/watch?v=kzcI5F4tGiU
- Оригинал (`.pi`): https://github.com/amosblomqvist/learn

## Что внутри

```
learn/
├── QWEN.md                        # контекст проекта (режим обучения, язык)
├── README.md
├── .qwen/
│   ├── skills/
│   │   ├── teach/SKILL.md         # ядро: два принципа + цикл проба→план→обучение
│   │   ├── quiz/SKILL.md          # оценённые вопросы через ask_user_question
│   │   ├── visualize/SKILL.md     # когда и как делать картинку
│   │   └── learn-log/SKILL.md     # ведение markdown-журнала
│   ├── agents/
│   │   ├── researcher.md          # веб-исследователь (проверка фактов, карта темы)
│   │   ├── mermaid-maker.md       # структурные диаграммы → PNG
│   │   └── svg-maker.md           # геометрические рисунки → PNG
│   └── commands/
│       ├── study.md               # /study <тема>
│       ├── quiz.md                # /quiz <тема>
│       └── mdlog.md               # /mdlog <путь>
├── scripts/
│   ├── render.mjs                 # Mermaid/SVG → PNG через headless Chrome
│   ├── log.mjs                    # ведение активного журнала
│   └── vendor/mermaid.min.js
├── lessons/                       # markdown-журналы занятий
└── viz/                           # исходники диаграмм и PNG
```

## Требования

- **Qwen Code** (эта среда использует проектные `.qwen/skills`, `.qwen/agents`, `.qwen/commands`).
- **Google Chrome** — только для рендера диаграмм. Другой путь задаётся переменной `CHROME_PATH`.
- Node.js — для `scripts/*.mjs` (уже есть в системе). Внешних npm-зависимостей нет.

## Как пользоваться

```bash
cd ~/Documents/learn
qwen
```

Дальше — обычными фразами («объясни, как работает TCP», «научи меня про event loop») или командами:

| Команда              | Что делает                                                            |
| -------------------- | --------------------------------------------------------------------- |
| `/study <тема>`      | Полная учебная сессия: проба → план → обучение, с ведением журнала.    |
| `/quiz <тема>`       | Быстрая проверка знаний с оценкой и обратной связью.                   |
| `/mdlog <путь>`      | Задать активный markdown-журнал (без аргумента — показать текущий).     |

В начале сессии создаётся журнал `lessons/<тема>.md`. Его удобно открыть в Obsidian — markdown, LaTeX (`$…$`) и картинки отрендерятся нативно.

## Как это работает

1. **Проба.** Сначала ищется *край* твоего понимания — серией оценённых вопросов, с резким повышением сложности на верных ответах. Отдельно выясняется учебная цель.
2. **План.** `researcher` очерчивает тему и вытаскивает настоящие «безусловные истины». Затем показывается план и mermaid-карта зависимостей. **Обучение не начинается без твоего одобрения плана.**
3. **Обучение.** Граф строится по одному узлу: мотивировать → установить → связать → проверить quiz-ом. Картинки добавляются через `visualize`, когда идея и правда яснее как картинка.

Факты, в которых модель не уверена, проверяются субагентом `researcher` — вместо выдумывания.

## Отличия от оригинала на `pi`

| Оригинал (`pi`)                    | Здесь (Qwen Code)                                                        |
| ---------------------------------- | ------------------------------------------------------------------------ |
| расширение `quiz` (свой UI-попап)  | протокол поверх встроенного `ask_user_question` (варианты + ручная оценка) |
| расширение `md-log` (авто-хук)     | `scripts/log.mjs` + skill `learn-log` (модель дописывает журнал сама)     |
| `ask-user-question` (расширение)   | встроенный инструмент `ask_user_question`                                 |
| `visual-tools` (кастомные тулзы)   | `scripts/render.mjs` + обычные `write_file`/`read_file`/`run_shell_command` |
| модели в агентах зафиксированы     | наследуются от основной сессии                                            |

## Настройка под себя

Главное правило оригинала: **система написана под одного ученика — тебя.** Правь `skills/teach/SKILL.md` под свой стиль: сколько зондировать в пробе, сократически или излагающе подавать, насколько крупными узлами идти. Это prompt-текст, менять можно свободно.

## Если что-то не работает

- **Диаграмма не рендерится:** проверь, что Chrome на месте (`ls "/Applications/Google Chrome.app"`), иначе задай `CHROME_PATH=/путь/к/chrome`.
- **Долгий рендер:** первый запуск Chrome прогревается дольше; сложные диаграммы лучше упрощать (это же рекомендует skill `visualize`).
- **Субагент не пишет файлы/не запускает команды:** у makers стоит `approvalMode: auto-edit`; если сессия запущена в `plan`-режиме, он перекрывает.
- **Journal не пишется:** проверь `node scripts/log.mjs current`; если пусто — `node scripts/log.mjs init "<тема>"`.
